# How to hand over your projects

One folder per project, in `projects/` of this private repository, so the files never become public. Claude can read everything here.

## 1. Where they go

Here, in **`zizocreates/portfolio-notes`** (private), inside `projects/`. On github.com, open this repository, go into `projects/`, and choose **Add file → Upload files**. Drag in a whole project folder. The browser takes files up to **25 MB** each; for bigger videos, see step 3.

## 2. One folder per project

```
projects/
  project-horizon/
    README.md        <- the template below, filled in
    code/            <- scripts, firmware, the repo link if it already lives elsewhere
    slides/          <- presentations, as PDF if you can
    photos/          <- as many as you like; Claude picks the best ones
    videos/          <- short clips under 25 MB, or a links.md for bigger ones
  snapstyle/
  basilbot/
  orch/
  mediflow/
  reservoir/
  payproof/
  autonomous-fan/
  aviation-expo-drone/
  school-tools/
  ...
```

Messy is fine. Claude sorts it.

## 3. Videos

**Short clips under 25 MB:** upload them in `videos/`. Claude can pull still frames out of a video and look at them, but **can't hear the sound**. Add one line per video in the README, such as "demo-1.mp4: the drone takes off, hovers 20 seconds, lands".

**Long or big videos:** upload them to YouTube as **Unlisted**. Put the link and the one-line description in `videos/links.md`. The site can embed or link them later.

**For the website,** the best video is 10 to 20 seconds of the thing working, with no talking. Trim before you upload if you can.

## 4. The README for each project (copy, fill in, skip what doesn't apply)

```markdown
# Project name

**One line:** what it is, in plain words.
**When:** month and year started; finished, or still going.
**Who:** solo, or with whom (and what was yours versus theirs).
**For:** a class, a client, a hackathon, yourself?

## The problem
Who had it, and why it mattered.

## What I built
How it works, step by step. The part you're proudest of.

## Stack
Languages, frameworks, hardware, APIs.

## The hardest bug or decision
What broke, how you found it, how you fixed it.

## Result
Numbers if you have them: users, time saved, emails handled, a placing, a mark.
Did it ship? Is it still running?

## Links
Live site, GitHub repo, demo video, slides.

## OK to show publicly?
Code: yes / no. Client name: yes / no. Screenshots: yes / no (blur anything private).

## Photos and videos
One line for each file you uploaded: what it shows.
```
